### Root cause found: ManagedClusterSet mismatch + broker CR never created (job 2081243880526712832)

- **Actual root cause (3 layers)**:
  1. Hub (`local-cluster`) is in `default` ClusterSet; each spoke is in its own ClusterSet

### deploy-odf — replace --for=create with polling loop for storageclusters CRD (job #2056517374441426944)
- **Root cause**: `odf-operator` is a meta-operator. Its CSV reaching `Succeeded` only means the `odf-operator` pod is running; it then asynchronously installs sub-operators (`ocs-operator`, `noobaa-operator`, `rook-ceph-operator`). The `storageclusters.ocs.openshift.io` CRD is owned by `ocs-operator` (a sub-operator) and does NOT exist at the moment `odf-operator`'s CSV is marked Succeeded. Running `--for=condition=Established` on a non-existent CRD fails instantly with NotFound.
- **Why previous `--for=create` removal was wrong**: Removing `oc wait --for=create` caused the `--for=condition=Established` to immediately hit NotFound instead of waiting. The `--for=create` was actually needed to gate on the CRD's existence.
- **Fix**: Replaced with a two-step approach: (1) poll with `oc get` until the CRD exists (up to 10 min), then (2) `oc wait --for=condition=Established`. This is more portable than `--for=create` (no client version dependency) and correctly models the async sub-operator installation flow.
### deploy-odf — remove hardcoded operator deployment wait (job #2056439890261839872)
- **Root cause**: `oc wait deployment/odf-operator` failed with `NotFound`. The operator deployment name varies across ODF versions and rhodf bundle releases — `ocs-operator` in pre-4.16, `odf-operator` in 4.16-4.19, and a different name again in 4.20. Any hardcoded name is fragile.
- **Why redundant**: OLM only marks a CSV as `Succeeded` after all deployments it manages are `Available`. Since Phase 2 already gates on `CSV phase=Succeeded`, the operator pod is guaranteed to be running and its reconciliation loop active — no further deployment wait is needed.
- **Fix**: Removed the `oc wait deployment/odf-operator` block entirely. Note: `oc wait --for=create` (also present) actually passed; it was not the cause of this failure.
### deploy-odf — remove unsupported oc wait --for=create
- **Root cause**: `oc wait --for='create'` was added to gate on the `storageclusters.ocs.openshift.io` CRD, but `--for=create` is only supported in `oc`/`kubectl` ≥ OCP 4.14 (Kubernetes 1.27). - **Fix**: Removed the `oc wait --for='create'` line; kept the `--for=condition=Established` belt-and-suspenders check which is safe on all supported client versions.

The ServiceExport, GlobalIngressIP, and broker ServiceImport remain intact — no new allocation cycle is triggered. Target lighthouse re-reads broker state (which now has the GlobalIngressIP in its EndpointSlice) and creates a fresh, non-poisoned local ServiceImport.

## 2026-05-13
### submariner-verify — fix Submariner v0.24.0 IPFamilyNotSupported race condition (job #2054570352700297216)
- **Root cause**: Race condition in Submariner v0.24.0. The lighthouse-agent on the target cluster reconciles the `ServiceImport` within ~1 second of creation. At that moment the `GlobalIngressIP` has not been allocated yet, so the Globalnet `EndpointSlice` has no endpoints and no `addressType`. The agent derives IP families from `EndpointSlice.addressType`; an empty EndpointSlice yields `IP families []` which fails the IPv4 compatibility check. Once `IPFamilyNotSupported` is set, the agent never self-heals — `status.ips` stays empty. Our earlier `ipFamilies: [IPv4]` fix on the Service was correct but addresses the wrong layer (lighthouse reads from EndpointSlice, not `Service.spec.ipFamilies`).
- **Fix**: After `subctl export service nginx`, wait (up to 180s) for `GlobalIngressIP` to be allocated on the source cluster (proving the EndpointSlice now has the correct IPv4 endpoint). Then force a lighthouse re-reconciliation by touching the `ServiceExport` with a `submariner.io/reconcile-ts` annotation and waiting 30s for propagation. The lighthouse-agent re-evaluates IP family compatibility with the correct EndpointSlice data and clears `IPFamilyNotSupported`.
- **File**: `ci-operator/step-registry/acm/interop-p2p/submariner-verify/acm-interop-p2p-submariner-verify-commands.sh`
